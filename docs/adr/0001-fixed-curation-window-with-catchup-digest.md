# Fixed curation window with a catch-up digest, not a frequency-scaling window

Delivery run frequency is configurable (daily, every N days, weekly, etc.), which could naturally imply the Curation window should scale to always cover "since the last digest." We chose a **fixed lookback window instead** (e.g. always the last 24h, independent of frequency), paired with a separate **Catch-up digest** that covers any gap left when a run is delayed or missed. A scaling window would make the Curation window's behavior depend on the frequency setting (more moving parts, harder to reason about what "top stories" means at a glance); a browsable web archive (the other alternative considered, for surfacing missed content) would require standing up new hosting/serving infrastructure. The fixed-window-plus-catch-up combination reuses the already-decided Send history mechanism to detect gaps, at much lower implementation cost than either alternative.
