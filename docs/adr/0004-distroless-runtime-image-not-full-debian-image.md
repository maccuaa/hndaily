# Distroless `oven/bun` runtime image, not the full Debian-based `oven/bun` image

ADR 0003 put the project in a long-running Docker container that runs `bun run src/index.ts`, originally on the full Debian-based `oven/bun` image, which ships a shell, `apt` and many OS packages the app never uses (it has no production dependencies, no native modules and spawns no child processes). We moved the release stage to the **official `oven/bun` `-distroless` variant**, pinned by tag and digest like the build stage, so the running container has no shell or package manager and far fewer OS packages to patch. This costs shell-based debugging (`docker exec … sh` no longer works; use `docker compose exec hndaily /usr/local/bin/bun -e '…'`), forces a numeric `USER 1000:1000` and `--chown` (there are no passwd entries), replaces `RUN mkdir`/`chown` in the release stage with a throwaway `data-dir` stage, needs the whole command in `ENTRYPOINT` so `--run-once`/`--dry-run` keep working as container args, and freezes the OS layers at Bun's release build — they refresh when Renovate bumps Bun rather than through `apt-get upgrade` — which the Recipient has accepted since the app does nothing that needs a shell.
